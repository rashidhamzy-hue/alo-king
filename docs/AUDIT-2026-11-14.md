# Gap audit, 14 November 2026 (planning chat, read-only checks on the repo, staging, Kapso and Sentry)

Twelve sessions are merged; main is green; staging runs an hourly order end to end. This lists what is still wrong or missing,
in order of risk. Each item names who fixes it. It is not the G1 audit (money, permissions, recovery, send path), which still has to run.

## A. Bugs seen on live staging
1. **False alarm every hour while closed.** `heartbeat:probe_silent` opens an exception each hour outside opening hours (12 open on
   14 Nov, plus Sentry issue `raiseAlarm`). The probe must not alarm when the shop is closed, and one open alarm must not be raised twice. Nobody resolves them. → A4
2. **Sentry noise.** Every deploy creates two "smoke test" issues (24 events each). Send them with a fingerprint that auto-resolves,
   or to a separate check, so a real error is visible. → A4
3. **Slow reply.** The founder's 07:00 message took 13.4 s from the fast model (target: most typed orders within 10 s). Measure
   p50/p90 from `agent_runs.latency_ms`, find the slow step (thinking budget raised to stop truncation in B3), fix. → A4 measures, lane B fixes
4. **Order after closing is not kept.** The reply lists the order but asks the customer to send it again after 08:00. Hold the basket
   and offer one button when the shop opens (inside the 24-hour window). → K1 (already in its row)
5. **Saved address from the buggy day.** The founder's saved place says Baakline while its pin is in Khraibeh (saved before "pin decides").
   Re-check every saved place against its pin once; ask on the next order where they disagree. → K1
6. **Cost is not recorded.** `agent_runs` stores tokens but no cost, so cost per order (4.11) cannot be read. Add a price table as data and a view. → A4
7. **1.23 not proven live.** `search_word_jobs` is empty on staging: no product has been added since B4. Add one test product on staging and watch its words appear. → D3 (through the console)
